# SMS-AI

Персональный SMS-шлюз к GigaChat через Plusofon.

Пользователь отправляет SMS на номер Plusofon. Plusofon вызывает webhook
FastAPI-приложения, приложение получает ответ GigaChat и отправляет его
пользователю через Plusofon API.

Постоянная база данных, Redis и автоматические рассылки не используются.

## Требования

- Python 3.12 или новее;
- номер Plusofon с поддержкой SMS;
- API-токен Plusofon;
- credentials GigaChat API для физического лица.

## Локальная установка в Windows PowerShell

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Заполните секреты и номера в `.env`. Файл `.env` нельзя добавлять в Git.

## Обязательные переменные окружения

```dotenv
APP_ENV=development
LOG_LEVEL=INFO
TIMEZONE=Asia/Yakutsk

PLUSOFON_TOKEN=
PLUSOFON_CLIENT_ID=10553
PLUSOFON_NUMBER_ID=
PLUSOFON_NUMBER=
PLUSOFON_WEBHOOK_TOKEN=
PLUSOFON_API_BASE_URL=https://restapi.plusofon.ru/api/v1

GIGACHAT_CREDENTIALS=
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat-3-Ultra
GIGACHAT_API_BASE_URL=https://api.giga.chat/v1
GIGACHAT_OAUTH_URL=https://ngw.devices.sberbank.ru:9443/api/v2/oauth
GIGACHAT_CA_BUNDLE=

ALLOWED_PHONE_NUMBERS=79991234567
```

Номера записываются в международном формате без символа `+`.

Несколько разрешённых номеров разделяются запятыми без пробелов:

```dotenv
ALLOWED_PHONE_NUMBERS=79991234567,79997654321
```

`GIGACHAT_CA_BUNDLE` обычно оставляется пустым. Если среда не доверяет
сертификату GigaChat, укажите путь к PEM-файлу доверенного CA bundle.

## Дополнительные настройки

```dotenv
MASTER_PIN=
AUTH_PIN=
DAILY_WARNING_THRESHOLD=5
MAX_CONTEXT_MESSAGES=8
DEFAULT_LATIN_MODE=off
SMS_PRICE_RUB=2.00
HTTP_TIMEOUT_SECONDS=15
NEWS_RSS_FEEDS=
```

`NEWS_RSS_FEEDS` — не секрет; позволяет переопределить или дополнить
встроенный allowlist RSS-лент команды `news` (по умолчанию — ТАСС, РБК,
Лента.ру, ЯСИА). Формат — список пар `Имя=https://url` через запятую,
например:

```dotenv
NEWS_RSS_FEEDS=ТАСС=https://tass.ru/rss/v2.xml,РБК=https://rssexport.rbc.ru/rbcnews/news/30/full.rss
```

Каждый URL обязан быть `https://`; пустое значение или значение без
корректных `https://`-адресов не подставляется как есть, а либо
приводит к использованию встроенных лент по умолчанию (для пустого
значения), либо к ошибке конфигурации при запуске (для некорректного
значения) — так через эту переменную нельзя выполнить SSRF на
внутренний/нестандартный адрес. Ленты задаются только через эту
переменную окружения при деплое; URL ленты нельзя передать через SMS, и
сервис не переходит по ссылкам, найденным внутри самих RSS.

Неизвестный номер может временно авторизоваться, отправив `<AUTH_PIN> auth`
(например, `9999 auth`). При правильном PIN номер получает доступ до
перезапуска приложения и SMS-подтверждение «Доступ разрешён до
перезапуска.». При неправильном PIN сообщение молча игнорируется.

Уже авторизованный номер (постоянный или временный) может сменить модель
GigaChat лично для себя командой `<MASTER_PIN> model <название>` (например,
`8241 model GigaChat-2-Pro`). При правильном PIN сервис запрашивает
актуальный список моделей через GigaChat Models API (`GET /v1/models`) и
проверяет точное совпадение id:

- модель найдена — выбор сохраняется в RAM до перезапуска для номера,
  отправившего команду, и приходит подтверждение «Модель: <название>»
  (канонический id из ответа API);
- модель не найдена — приходит «Модель недоступна.», настройка не
  меняется;
- Models API недоступен — приходит «Модели сейчас недоступны :(»,
  настройка не меняется.

При неверном `MASTER_PIN` команда молча игнорируется и не попадает в
GigaChat. PIN-коды должны отличаться друг от друга.

Авторизованный номер (постоянный или временный) может использовать
служебные команды:

- `stat` (`stats`/`стат`) — статистика: сегодняшние и месячные SMS-сегменты
  (по полю `pdu` через историю Plusofon), число AI-запросов с момента
  запуска, текущая модель и оценка стоимости месяца
  (`monthly_pdu * SMS_PRICE_RUB`). Если история Plusofon недоступна,
  приходит короткая ошибка «Статистика недоступна :(», обычный AI-ответ при
  этом не блокируется;
- `models` — список доступных моделей генерации GigaChat (эмбеддинг-модели
  исключаются) и текущая модель для этого номера, без `MASTER_PIN`. Если
  Models API недоступен или не вернул ни одной модели генерации —
  «Модели сейчас недоступны :(»;
- `latin on` / `latin off` — включает/выключает персональный режим
  транслита (ответ «Latin: ON» / «Latin: OFF»). При включённом режиме к
  системной инструкции GigaChat для этого номера добавляется просьба
  писать русский текст латиницей, не переводя на английский. Работает и
  для обычных вопросов, и для `+`. Без `MASTER_PIN`, хранится в RAM
  отдельно для каждого номера и сбрасывается после перезапуска
  (по умолчанию — `DEFAULT_LATIN_MODE`);
- `clear` (`сброс`) — создаёт персональную границу контекста в RAM: более
  старые SMS не подмешиваются в новые AI-запросы, пока не перезапущено
  приложение. Ответ — «Новый диалог.»;
- `+` — просит GigaChat продолжить последний ответ, используя последний
  вопрос и последний ответ из истории диалога Plusofon. Если продолжать
  нечего (например, последний вопрос ещё не отвечен, диалог пуст или
  весь предыдущий диалог отрезан границей `clear`), приходит
  «Продолжения нет.»;
- `help` (`помощь`) — короткая справка по всем командам первой версии;
- `calc [выражение]` — калькулятор: `+`, `-`, `*`, `/`, скобки, унарный
  минус/плюс, постфиксный `%` у числового литерала (например, `50%` →
  0.5). Выражение разбирается через `ast.parse` со строгим списком
  разрешённых узлов — `eval`/`exec`/`compile` пользовательского текста
  никогда не вызываются, вычисление не уходит в GigaChat. Компактные
  ошибки: «Пустое выражение.», «Некорректное выражение.», «Деление на
  ноль.»;
- `translate [текст]` — перевод через GigaChat с отдельной системной
  инструкцией (только перевод, без пояснений и Markdown). Если после
  `translate` указан двухбуквенный код языка (`translate en Привет`,
  `translate ru Hello`) — это целевой язык; иначе язык определяется
  автоматически по наличию кириллицы: русский текст → английский, любой
  другой → русский. При недоступности GigaChat — «ИИ поломался :(» (тот
  же стандартный текст, что и для обычного ответа);
- `wiki [тема]` — краткая справка из публичного Wikipedia REST API (без
  ключа, `ru.wikipedia.org`, без ссылок по умолчанию), обрезанная по
  границе предложения. «Укажите тему: wiki <тема>.» на пустую тему,
  «Статья не найдена.» на 404/пустой ответ, «Википедия сейчас недоступна
  :(» на timeout/5xx/невалидный ответ;
- `weather [город]` — текущая погода и ночной минимум через публичные
  Open‑Meteo API (без ключа): геокодирование (`geocoding-api.open-meteo.com`)
  находит координаты города, `api.open-meteo.com/v1/forecast` отдаёт
  текущую температуру, код погоды WMO и скорость ветра, а также минимум
  за сутки. Код WMO переводится в короткое русское состояние (`ясно`,
  `облачно`, `дождь`, `снег`, `гроза` и т.д.) локально, без обращения к
  GigaChat. «Укажите город: weather <город>.» на пустой город, «Город не
  найден.» на пустой результат геокодирования, «Погода сейчас недоступна
  :(» на timeout/5xx/невалидный ответ;
- `currency [BASE] [QUOTE]` (например, `currency USD RUB`) — курс через
  публичный Frankfurter API (без ключа, `api.frankfurter.dev`), коды
  регистронезависимы на входе и приводятся к верхнему регистру в ответе.
  Курс хранится и форматируется через `Decimal` без scientific notation, с
  адаптивным числом знаков после запятой (2–6, без лишних нулей), чтобы не
  терять значимые цифры для маленьких курсов. «Укажите валюты: currency
  USD RUB.» при отсутствии/неверном числе аргументов, «Неверный код
  валюты.» если код не из трёх латинских букв, «Курс сейчас недоступен
  :(» на 400/404/timeout/5xx/невалидный ответ;
- `news [тема]` — свежие новости без ключей и секретов:
  - `news` без темы — несколько главных свежих новостей;
  - `news <тема>` (например, `news ИИ`, `news космос`, `news Якутия`,
    `news Apple`) — свежие новости по теме.

  Источники — только заранее заданный allowlist RSS/Atom-лент (URL лент
  никогда не принимаются через SMS и по ссылкам из самих RSS сервис не
  переходит):
  - встроенные российские ленты по умолчанию — ТАСС, РБК, Лента.ру, ЯСИА
    (последняя — региональный источник по Якутии); список можно
    переопределить/дополнить через `NEWS_RSS_FEEDS` (см. ниже);
  - Google News RSS (`news.google.com/rss`, `.../rss/search`) — только
    как дополнительный источник.

  Логика устойчивости: без темы сервис сначала агрегирует, дедуплицирует
  и сортирует по свежести все российские ленты; к Google News переходит,
  только если ни одна российская лента не дала результата. По теме
  сначала ищет её локально по заголовкам/описаниям/категориям уже
  полученных российских лент и лишь дополняет результат через Google
  News, если российских элементов недостаточно. Отказ одной ленты (или
  Google) не блокирует ответ, пока другие источники дают результат;
  дубликаты одной новости из разных лент объединяются в одну запись с
  указанием всех источников — результат одного СМИ не выдаётся за
  подтверждённый несколькими источниками факт. Найденные новости (без
  ссылок — они пользователю не отправляются) сжимает GigaChat по
  отдельной строгой системной инструкции: только факты из переданных
  новостей, без данных из памяти модели, 1–3 пронумерованных пункта на
  русском, без Markdown/ссылок/URL. Обычный диалоговый контекст в этот
  запрос не подмешивается. «Новости сейчас недоступна :(» — если после
  всех источников (российские ленты и Google News) не осталось ни одной
  пригодной свежей новости; при недоступности GigaChat на этапе сжатия —
  «ИИ поломался :(» (тот же стандартный текст, что и для обычного
  ответа).

Все команды выше (кроме `stat`/`models`/`clear`/`latin`, которые не
трогали в этих изменениях) сериализуются той же блокировкой по номеру,
что и обычный AI-ответ, — параллельные SMS от одного номера не
перемешиваются.

Перед обычным AI-ответом сервис подмешивает в запрос GigaChat контекст —
до `MAX_CONTEXT_MESSAGES` последних сообщений диалога из истории Plusofon
(`GET /api/v1/sms/dialog/{number}`), исключая служебные команды (`auth`,
`model`, `models`, `stat`, `clear`, `latin on/off`, `help`, `calc`,
`translate`, `wiki`, `weather`, `currency`, `news`, `+`) и технические
уведомления/ответы этих команд — в том числе любые сообщения, содержащие
PIN. Для `help`/`calc`/`translate`/`wiki`/`weather`/`currency`/`news` из
контекста исключается весь обмен целиком: сама команда и все её исходящие
SMS вплоть до следующего входящего сообщения, — это не зависит от текста
ответа и одинаково работает для успешного результата и для ошибки, так
как эти ответы динамические (число, перевод, погода, курс, новости) и не
могут быть распознаны по фиксированному тексту. Если история Plusofon
недоступна, GigaChat всё равно получает ответ, но без контекста — это не
блокирующая ошибка.

## SMS formatter и предупреждение `[!]`

Перед отправкой ответа GigaChat (обычный вопрос или `+`) сервис:

- убирает Markdown (заголовки, списки, `**жирный**`/`*курсив*`, `` `код` ``,
  таблицы, ссылки `[текст](url)` → `текст (url)`) и лишние пробелы/переносы;
- определяет кодировку — GSM-7 (латиница/цифры) или UCS-2 (кириллица,
  эмодзи и т.д.) — и делит текст на физические SMS-сегменты по границам
  слов, не разрывая слова без необходимости (ориентир: одиночная
  GSM-7 ~160 / составная ~153 символа на сегмент; UCS-2 — ~70 / ~67);
- добавляет служебные префиксы `[i/N]` в каждый сегмент составного
  ответа;
- перед отправкой запрашивает у Plusofon сегодняшние исходящие SMS этого
  номера (`incoming=0`, `receiver=<номер>`); если их физических сегментов
  уже отправлено `DAILY_WARNING_THRESHOLD` или больше, первый сегмент
  ответа получает префикс `[!]` (мягкое предупреждение, не лимит; ответы
  никогда не блокируются). Если Plusofon недоступен — предупреждение
  просто не ставится, ответ всё равно уходит.

Сегменты отправляются по одному, строго по порядку.

## Тесты

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Тесты используют mock-серверы и не обращаются к реальным API. Они не расходуют
токены GigaChat и не отправляют SMS.

## Проверка импорта

```powershell
.\.venv\Scripts\python.exe -c "from app.main import app; print(app.title, app.version)"
```

Ожидаемый результат:

```text
SMS-AI 0.1.0
```

## Реальная E2E-проверка

Mock-тесты не подтверждают интеграцию с production API. После ручного деплоя
точного commit SHA выполните отдельную проверку через физический телефон по
[чеклисту](docs/e2e.md).

Smoke-скрипты запускаются как Python-модули из корня репозитория. Реальная
отправка Plusofon дополнительно требует явный флаг `--confirm-send`; CI этот
флаг не использует и SMS автоматически не отправляет.

## Локальный запуск

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload --no-access-log
```

Проверка из второго окна PowerShell:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health
Invoke-RestMethod http://127.0.0.1:8000/ready
```

Ожидаемые ответы:

```text
status
------
ok

status
------
ready
```

Локальный адрес недоступен Plusofon из интернета. Не указывайте его как
webhook в личном кабинете.

## HTTP endpoints

- `GET /health` — процесс приложения работает;
- `GET /ready` — конфигурация и внутренние клиенты созданы;
- `POST /webhooks/plusofon/incoming/<token>` — входящие SMS Plusofon.

Проверки `/health` и `/ready` не обращаются к Plusofon или GigaChat.

## Timeweb Cloud App Platform

Команда сборки:

```bash
pip install --upgrade -r requirements.txt
```

Команда запуска:

```bash
uvicorn app.main:app --host 0.0.0.0 --port ${PORT:-8000} --no-access-log
```

Путь проверки состояния:

```text
/ready
```

Все значения из `.env` задаются в панели Timeweb как переменные окружения.
Сам файл `.env` в репозиторий не загружается.

Для GigaChat в настройках приложения могут понадобиться доверенные российские
корневые сертификаты. Production-деплой выполняется вручную только после
успешных локальных тестов.

## Безопасность

- не публикуйте `.env`;
- не передавайте API-токены в URL или query-параметрах;
- используйте длинный случайный `PLUSOFON_WEBHOOK_TOKEN`;
- не включайте стандартный access-log: webhook-токен является частью URL;
- разрешайте только личные номера через `ALLOWED_PHONE_NUMBERS`;
- не запускайте несколько экземпляров приложения: порядок SMS хранится в RAM.
